# Notion Watch · 本地只读

通过现有 Notion 登录会话，定期查看一个入口页及发现的子页面，记录「谁最近更新了哪个页面」。适合没有空间管理员权限的合作空间访客。

**当前版本：0.2.0。** Chrome 120+，开发者模式安装；尚未上架 Chrome 应用商店。Notion 的页面布局变化可能导致读取失败；首版不保存正文，也不提供正文 diff。

## 安装与开始

1. 从 GitHub Releases 下载 `notion-watch-0.2.0.zip`，解压到一个固定目录。
2. 打开 `chrome://extensions`，开启开发者模式，选择「加载已解压的扩展程序」，选中含 `manifest.json` 的 `notion-watch` 文件夹。
3. 点击扩展图标，进入「订阅设置」，填写你自己的 **`https://app.notion.com/…`** 页面或数据库链接，点击「保存设置」。其他 Notion 域名暂不支持；请在登录后的网页复制 `app.notion.com` 链接。
4. 点击「授权读取 Notion」。同一个 Chrome 用户配置中必须已经登录 Notion，且有权访问入口及子页。
5. 返回「更新收件箱」，点击「检查更新」。首次完整成功检查建立基线，不把旧编辑当作新动态。
6. 后续检查显示页面标题、最近编辑者、编辑时间及所属周报。点击标题打开原文，或用勾号标为已读。

升级时，停止旧轮次，**覆盖原加载目录的文件并重新加载扩展**；不要卸载或改用新目录，以保留扩展 ID、本地设置与基线。0.1.x 已保存的入口仍然保留；新安装没有任何私人入口预设。

## 日常功能

| 功能            | 行为                                                                 |
| --------------- | -------------------------------------------------------------------- |
| 左侧导航        | 独立切换收件箱、订阅设置、运行日志；浏览器前进/后退可用              |
| 未读 / 全部动态 | 按检测日期分组；每条显示页面的编辑时间，不把检测时间冒充编辑时间     |
| 搜索与已读      | 搜索标题、最近编辑者、所属周报；有搜索条件时批量已读只作用于筛选结果 |
| 自动检查        | 勾选、保存后按 15/30/60/120 分钟检查；默认关闭                       |
| 桌面通知        | 勾选、保存并授予可选通知权限后提醒；系统通知设置仍可能阻止显示       |
| 折叠检查标签页  | 可选标签组权限；只分组扩展自建的后台页，组名仍可见，完成后清理       |
| 日志 / 页面索引 | 查看本轮进度、最终失败、覆盖限制与每页最近成功记录                   |
| 失败页重试      | 有上一轮失败页时才可用，仅检查这些页面；不会重跑全部子树             |
| 更换入口        | 保存后切换到独立记录；切回原入口可继续使用原基线与历史               |

勾选后会显示「有未保存的更改」。点击「保存设置」才会生效，后台状态刷新不会清除草稿。保存后重新打开页面仍保留设置。「撤销未保存更改」恢复已保存选项。检查期间设置被禁用，避免一轮检查中途改变行为。

## 高级设置

- **同时检查 1–6 页**：默认四页。降低并行可减少浏览器占用。
- **只检查近期周报**：按子页标题中的 `11.16-11.22` 日期范围判断。周一包含前一周，其他时间检查本周及更新的周报。无法解析标题时继续检查。普通项目不需要周报筛选时可关闭。
- **增量扫描**：作者/时间未变化且上次扫描没有覆盖限制时，复用已发现子页；24 小时重新发现一次。新增子页可能延迟到缓存刷新，需即时发现可关闭增量扫描。
- **快速切换（实验，默认关闭）**：尝试 Notion 前端路由，失败时回退整页加载；布局或路由变更可能影响此项。
- **独立检查窗口（实验，默认关闭）**：可见的小窗口，一次一页，不主动抢焦点。切过去操作或最小化会暂停。完全遮挡时仍可能被页面视为隐藏；不保证提速。

自动检查使用已保存的设置。点击「停止检查」停止当前轮次；若希望以后也不检查，请取消自动检查并保存。

## 能力边界

这不是完整编辑日志。两次检查之间多人修改时，通常只读到最后一位编辑者；同一人同一分钟的修改可能合并。不会推断评论作者就是正文编辑者，也不保证覆盖评论、附件或所有属性变化。

扫描受当前数据库视图、懒加载、内嵌数据库和折叠内容影响。只递归可识别的真实子页区块，不把正文中所有 Notion 超链接都当成子页。最多 200 页、8 层。覆盖受限会写入日志，零失败也不等于完整覆盖所有隐藏页面。

检查会创建不激活的 Notion 标签页。不能保证完全隐藏；打开检查页操作会暂停本轮。结束、停止或暂停时只清理仍属于扩展、未被用户接管的页。浏览器退出、电脑休眠、登录失效期间无法检查，恢复后也无法补齐所有中间编辑。

## 隐私与权限

数据仅保存在当前浏览器的扩展存储中。扩展不上传页面数据，不调用 Notion 私有 API，不提取登录凭证，不修改正文、评论、筛选、共享或通知设置。访问页面可能留下在线状态或访问记录。

必需权限为 `storage`、`alarms`、`scripting`。Notion 站点权限、桌面通知和标签组权限按需请求；没有申请所有网站、浏览历史或 Cookie 权限。详见 [隐私说明](PRIVACY.md)。

## 开发与验证

需要 Node.js 22+；CI 使用 Node.js 24。

```sh
npm ci
npm run check
npm test
npm run build
npm run package
```

`dist/` 可直接加载到 Chrome；`release/` 含安装 ZIP。生产包不含演示数据、测试文件、凭证或用户运行日志。

```sh
npm run preview
```

本地演示位于 `http://127.0.0.1:8974`，只使用合成数据和模拟扩展 API，不连接 Notion，不授予真实权限。修改源码后重启预览。它用于检查导航、保存、筛选和排版，不能替代真实扩展及 Notion 验证。

自动测试覆盖页面读取、停止/接管保护、增量缓存、时间解析、自动检查事件、通知、设置持久化、跨入口数据隔离，以及实际构建脚本的界面交互。测试通过不能保证兼容所有 Notion 布局。问题反馈请参考 [贡献与验收说明](CONTRIBUTING.md)。
